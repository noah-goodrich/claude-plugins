# ai-scoring Baseline — 2026-08-20

Measured before `ai-scoring/SKILL.md` gained its scanning-document mode. This file is the regression detector for
that change. The mode is rule text, not code, so nothing about it can be unit-tested; the only way to notice it
drifting is to re-run the numbers below and compare.

## Reproduce

Run from the corpus directory. Both commands are copy-pasteable as one block:

```
cd /Users/noah/dev/claude-plugins/noah-writing-voice/validation/2026-05-23-corpus && \
FIX=/Users/noah/dev/claude-plugins/noah-content-tools/skills/design-doc/test/fixtures/real && \

  "$FIX/2026-08-20-communication-program.md" \
  "$FIX/2026-08-20-comms-delivery-surfaces.md" \
  "$FIX/2026-08-20-design-doc-and-brevity-skills.md" \
  "$DIR/2026-08-14-experiment-skill.md" \
  "$DIR/2026-06-29-token-cost-optimization.md" ; \
python3 scripts/ai_score.py --batch articles
```

Measured with Python 3.14.3 against the working tree of `feat/design-doc-brevity-pr-description-2026-08-20`, base
commit `4947095`. Every input is inside `claude-plugins`, so the block reproduces from a single clone with no
second repository present. `ai_score.py` is deterministic and has no network or state, so the same inputs give the
same output on any machine.

### Why these paths

Three of these directives were drafted in `borg-collective`, where they are still untracked working files. Do not
re-point this table at them. Between the first run of these numbers and the same day's verification pass,
`/Users/noah/dev/borg-collective/docs/plans/directives/2026-08-20-comms-delivery-surfaces.md` went from 1070 words
and score 85 to 1352 words and score 78, because the live file was being edited while the baseline was written.
The acceptance rule at the bottom of this file failed on the day it shipped. A detector anchored to a file another
process can rewrite is not a detector.

The three `$FIX` copies are frozen snapshots of those directives taken at the moment they were measured. They live
in this repo as fixtures for the `design-doc` skill's test suite, they land in history with this branch, and they
change only through a reviewed edit here.

`2026-08-14-experiment-skill.md` and `2026-06-29-token-cost-optimization.md` keep their `$DIR` paths. Both are
already tracked in this repo and clean in `git status`, so they are as stable as the snapshots; copying them would
only add a second thing to keep in sync.

## What the numbers show

**The directives outscore the published articles.** Directive mean is 82.4; article mean is 73.0. The lowest
directive (75) beats five of the ten articles. Whatever the rubric is measuring on directives, it is not "this
reads as machine-written" — the documents it penalizes score better than the human-written corpus it was built
for.

**The penalties are format, not tells.** Three categories account for one hundred percent of the directive
penalty, and each one fires on something the directive template requires: a status line, a `Non-Goals` list, and
the em dash. Category 3 (generic transitions), category 4 (hedging), category 6 (lists as prose) and category 7
(missing specifics) — the four categories that describe actual AI habits rather than shape — never fire on any of
the five. That split is the whole argument for a second mode.

**The em-dash clause is the largest single line item.** It costs the five directives 43 points of the 88 they lose
in total. `voice-rules.md:10` bans em dashes outright; these five documents contain 54 of them, by both the
scorer's count and a raw `grep -o` over the files. `PROJECT_PLAN.md` D2 cites 48 for the same five; that figure is
stale, and 54 is the measured number at the anchored paths above. The direction of the argument is unchanged.

**Category 5 measured zero.** Repetitive sentence openings never fired on a directive. It is disabled in scanning
mode on the same reasoning as category 2, not on measured damage. Recording that here so nobody later mistakes it
for an observed result.

**Scanning mode gives all five a clean sheet.** Scoring only categories 3, 4, 6 and the category-8 word list, every
directive scores 100, since all four inputs measured zero. That is the honest state of it: on this corpus the new
mode has no discriminating power yet. What it does have is a floor — a future design doc that reaches for "let's
dive in", hedges instead of deciding, stacks discrete facts into a fake paragraph, or says "leverage" will drop
below 100 and say so. The mode exists to stop the rubric from punishing required format, and to keep the four
checks that still mean something.

## Using this file

Re-run the command block after any edit to `ai-scoring/SKILL.md`, `voice-rules.md` or `ai_score.py`. Article-mode
scores in the second table must not move; if one does, the change was not additive. Directive scores must be at or
above the numbers in the first table.

Both halves are anchored to files inside this repo, so a moved number means the rubric moved. If an input file
itself changes, that is a separate decision: re-measure and re-record the row in the same commit, and say in the
commit message that the input moved rather than the rubric.
